本章节将介绍在YashanDB单机数据库上进行Sysbench性能测试的具体操作及相关示例。

> **Caution**：
>
> 压测客户端应与数据库实例直接连接，确保网络延时<0.2ms，避免网络成为性能瓶颈。

## 安装Sysbench

推荐使用官方预编译包进行安装：

```bash
## root用户
# curl -s https://packagecloud.io/install/repositories/akopytov/sysbench/script.rpm.sh | bash
# yum -y install sysbench

# 非root用户（必须具备sudo权限）
$ curl -s https://packagecloud.io/install/repositories/akopytov/sysbench/script.rpm.sh | sudo bash
$ sudo yum -y install sysbench
```

验证安装结果：

```bash
$ sysbench --version
sysbench 1.1.0
```

## 安装YashanDB客户端

Sysbench通过YashanDB C驱动连接YashanDB，YashanDB C驱动安装文件集成在YashanDB客户端安装包中，需要安装YashanDB客户端以提供必要的库文件。

1. 从YashanDB官网下载中心（[https://download.yashandb.com/download](https://download.yashandb.com/download)）或联系我们的技术支持获取对应的软件包。

2. 解压安装包：

   ```bash
   tar -zxvf yashandb-client-xx.xx-linux-x86_64.tar.gz -C /home/
   ```

3. 配置环境变量：

   ```bash
   # 编辑bashrc文件
   $ vi ~/.bashrc
   
   # 添加库路径
   $ export LD_LIBRARY_PATH=$LD_LIBRARY_PATH:/home/yashandb-client-xx.xx-linux-x86_64/lib
   
   # 刷新配置
   $ source ~/.bashrc
   ```

## Sysbench相关配置介绍

### 数据库连接参数

Sysbench使用以下参数连接YashanDB：

```bash
--yashan-db="192.168.1.2:1688" \
--yashan-user="sysbench" \
--yashan-password="$YASHAN_PASSWORD"
```

| 参数 | 说明 |
| --- | --- |
| --yashan-db | 数据库连接地址，格式为`host:port` |
| --yashan-user | 数据库用户名，需具备CONNECT和RESOURCE权限 |
| --yashan-password | 数据库用户密码 |

### 通用参数

| 参数 | 说明 | 默认值 |
| --- | --- | --- |
| --threads=N / --num-threads=N | 并发测试线程数 | 1 |
| --time=N / --max-time=N | 总执行时间上限，单位秒（0表示不限制） | 0 / 10 |
| --report-interval=N | 每隔N秒输出一次中间统计报告（0表示禁用） | 0 |
| --percentile=N | 延迟统计的百分位值 | 95 |
| --thread-init-timeout=N | 线程启动时间 | 60 |
| --tables=N | 测试表的数量 | / |
| --table-size=N | 每张表的行数 | / |

## 运行Sysbench测试

### 部署YashanDB数据库

具体的YashanDB数据库安装与部署操作，请查阅产品文档中的[安装部署](https://doc.yashandb.com/yashandb/23.4/zh/Install-Guide/00Install-Guide.html)。

性能数据会因为测试环境的CPU、内存、IO、网络条件差异而不同，为了让YashanDB在测试环境上达到最佳性能，需要根据测试环境的配置进行性能调优。数据库性能调优的详细信息请查阅[调优思路](调优思路.md)。

Sysbench测试调优主要关注以下方面：

**数据库建库配置调优**

如果存储条件允许，请将redo文件与数据文件分盘部署，以减少两者间的IO争用。

| 配置项 | 推荐值 |
| --- | --- |
| redo分盘部署 | 大小 50G * 10，BLOCKSIZE 512 |
| undo大小 | 增大到40G |
| tablespace  | 根据实际数据量创建，需提前创建 |

推荐直接在安装时通过配置建库参数构建测试数据库。

| 配置项 | 参数说明 | 推荐值 |
| --- | --- | --- |
| REDO_FILE_NUM | redo文件的数量 | 10 |
| REDO_FILE_PATH | redo文件的路径，需分盘存储 | / |
| REDO_FILE_SIZE | redo文件的大小 | 50G |
| UNDO_FILE_INIT_SIZE | UNDO表空间的初始大小 | 40G |
| SWAP_FILE_INIT_SIZE | SWAP表空间的初始大小 | 10G |
| SYSTEM_FILE_INIT_SIZE | SYSTEM表空间的初始大小 | 5G |
| SYSAUX_FILE_INIT_SIZE | SYSAUX表空间的初始大小 | 5G |
| DATA_FILE_INIT_SIZE | 默认数据表空间的初始大小 | 300G |


**数据库[配置参数](https://doc.yashandb.com/yashandb/23.4/zh/All-Manuals/Reference-Manual/Configuration-Parameters.html)调优**

在Sysbench测试场景下，主要关注缓存大小与并发参数的配置：

```sql
-- 数据缓冲区大小，用于缓存数据块，建议配置为规划内存的80%
DATA_BUFFER_SIZE=200G

-- 数据缓冲区分区数，大并发场景下可降低缓存区锁冲突
_DATA_BUFFER_PARTS=8

-- 虚拟机缓冲区大小，用于保存排序等操作的中间结果
VM_BUFFER_SIZE=25G

-- 虚拟机缓冲区分区数
VM_BUFFER_PARTS=8

-- Undo保留时间，降低undo保留时间可提高小事务场景下的性能
UNDO_RETENTION=15

-- 检查点超时时间
CHECKPOINT_TIMEOUT=900

-- 共享池大小
SHARE_POOL_SIZE=2G

-- 语句级一致性写入，测试完成后建议还原相关配置（若环境并非专门用于Sysbench测试，推荐为测试表添加row movement属性以实现一致性写入效果）
_CONSISTENT_WRITE=TRUE
```

### 准备测试数据（prepare阶段）

> **Note**:
>
> - 为避免之前测试的数据残留影响测试结果，建议在prepare前先执行cleanup清理旧数据。
>
> - 重复测试时，推荐手动执行checkpoint，并切换redo。
>
> - 测试表数量建议不低于10张，单表数据量不低于500万行（使用SSD时可提升至1亿行以上）。

进入Sysbench目录，准备测试数据（创建表和填充数据）。

```bash
$ cd /home/yashan/sysbench

$ /home/yashan/sysbench/src/sysbench /home/yashan/sysbench/src/lua/oltp_read_write.lua \
--report-interval=5 \
--tables=10 \
--table_size=100000 \
--yashan-db="192.168.1.2:1688" \
--yashan-user="sysbench" \
--yashan-password="$YASHAN_PASSWORD" \
--threads=128 \
prepare
```

执行上述命令后，Sysbench会自动创建类似以下固定结构的表，并围绕目标表展开相关测试，通过组合多种SQL语句来模拟在线事务处理负载。

建表语句为：

```sql
CREATE TABLE sbtest1 (
  id int(10) unsigned NOT NULL AUTO_INCREMENT,
  k int(10) unsigned NOT NULL DEFAULT '0',
  c char(120) NOT NULL DEFAULT '',
  pad char(60) NOT NULL DEFAULT '',
  PRIMARY KEY (id),
  KEY k_1 (k)
);
```

表结构解析如下：

|列名 |数据类型 | 索引 | 特点 |
|---|---|---|---|
|id|int(10) unsigned|主键索引 (PRIMARY KEY)|默认自增，可通过--auto_inc=off禁用|
|k|int(10) unsigned|二级索引 (KEY k_1)|核心索引列，用于模拟索引查询和更新，可通过--create_secondary=off禁用|
|c|char(120)|无|定宽字符列，模拟非索引数据，增加行宽和数据量|
|pad|char(60)|无|定宽字符列，模拟非索引数据|

该表通过**索引列k**与**非索引列c和pad**的组合，有效考察数据库在不同IO模式和锁竞争下的行为，模拟了典型的业务表结构。


### 运行测试（run阶段）

在测试过程中，应尽量避免重启数据库。重启会导致脏页写入磁盘，引发大量磁盘读取操作，进而对性能产生不利影响。若确实必须重启，那么在重启后可以先运行一段时间只读（read_only）场景的测试将数据加载到缓存中。

#### 只读（read_only）测试

在Sysbench目录中执行如下命令进行只读测试。

```bash
$ /home/yashan/sysbench/src/sysbench /home/yashan/sysbench/src/lua/oltp_read_only.lua \
--report-interval=5 \
--tables=10 \
--table_size=100000 \
--yashan-db="192.168.1.2:1688" \
--yashan-user="sysbench" \
--yashan-password="$YASHAN_PASSWORD" \
--time=600 \
--threads=256 \
--thread-init-timeout=1000 \
run \
--percentile=99
```
